Build a bot for Zuno

Zuno bots are accounts that sign in with a token, get live events, and use the same API as the app. Any language that can make HTTP requests works.

Getting started

  1. In Zuno, open Settings › Developer and press New Bot. Copy the token straight away: it's only shown once. If it leaks, press Reset Token.
  2. Press Add to Server to put the bot in a server you manage. You choose which permissions it gets.
  3. Run your code. It connects to the live event stream, registers its commands and answers messages.

All requests go to https://heyzuno.uk. Send and receive JSON (Content-Type: application/json). Errors come back with a status code and {"error": "A friendly message"}.

Signing in

Send the token in the Authorization header on every request:

Authorization: Bot YOUR_BOT_TOKEN

Bots can only call the endpoints listed under Endpoints. Anything else answers 403 Bots can't use that part of the API.

Never put your token in code you share, a public repo or a message. Anyone with it can act as your bot.

Live events

Open one long-lived request to GET /api/events with your bot token. Zuno sends server-sent events: blocks separated by a blank line, each with an event: name and a JSON data: line. A comment line (: ping) arrives every 25 seconds to keep the connection open.

id: 1042
event: message
data: {"conv":"ch:abc123","serverId":"sv1","channelId":"abc123","message":{...}}

If the connection drops, reconnect with ?last=<id> (the last id: you got). Zuno replays what you missed from the last ~2 minutes and then sends resumed. If it can't, you get resync: fetch whatever state you need again.

Your bot also receives its own messages. Check message.authorId against your bot's id (from GET /api/me) so it doesn't answer itself.

Slash commands

Register up to 25 commands. They show in the / menu of every server your bot is in:

PUT /api/bots/@me/commands
{ "commands": [
  { "name": "roll", "description": "Roll a dice", "usage": "[sides]" },
  { "name": "ping", "description": "Check the bot is awake" }
] }
  • name: 1 to 32 characters, lowercase letters, numbers, - and _.
  • description: up to 100 characters. usage: up to 60, shown as a hint.
  • Sending the list replaces the old one. GET /api/bots/@me/commands returns the current list.

When someone sends /roll 20, you get a command event with name: "roll" and args: "20". Everyone in the channel sees "Bot is thinking…" until your bot posts in that channel, and your answer appears under a small "Name used /roll" line. Answer within a few seconds, and reply to messageId to make the link clear.

People need the Use Bot Commands permission in that channel. If two bots have the same command name, the one that joined the server first gets it.

Your bot can only hand out permissions and roles it has itself, and only change roles below its own. Server owners decide where its role sits in Server Settings › Roles.

DMs

Your bot can message anyone who shares a server with it, unless they turned off Messages from bots in their privacy settings. People can write back. Send with POST /api/dms/:userId/messages (the same body as a channel message). Incoming DMs arrive as a message event whose conv is the person's user id (there's no serverId). Up to 30 DMs a minute per bot. Don't DM people who didn't ask for it: bots that spam DMs get removed.

Messages

Send a message:

POST /api/channels/:id/messages
{ "content": "Hello! 👋", "replyTo": "messageId", "replyPing": false }

replyTo and replyPing are optional. replyPing: false replies without notifying the person. Messages can be up to 2000 characters.

A message looks like this (some fields only appear when used):

{
  "id": "mwx1...",            "authorId": "user id",
  "content": "text",          "createdAt": 1794675293401,
  "editedAt": 1794675299000,  "replyTo": { "id": "...", "authorId": "..." },
  "mentions": ["user id"],    "reactions": { "👍": ["user id"] },
  "attachments": [{ "id": "...", "url": "/uploads/...", "name": "cat.png", "size": 48213, "kind": "image" }],
  "command": { "name": "roll", "botId": "..." },  "pinned": true

Permissions

A bot follows the same rules as people. When it's added, it gets its own role with the permissions you ask for in Settings › Developer (people can only give ones they have themselves). Channel settings can still allow or deny things per channel.

To kick, ban or change roles, your bot's role has to be above the person's highest role, and it can never act on the server owner.

Webhooks

For posting only (alerts, feeds, build results), a webhook is simpler than a bot. Make one in Server Settings › Bots & Webhooks, copy its URL, and post to it. No token header needed:

POST /api/webhooks/:webhookId/:secret
{ "content": "Build passed ✅", "username": "CI", "avatarUrl": "https://example.com/ci.png" }

Webhooks can post 30 messages a minute and can't ping @everyone or roles.

Limits

  • 25 messages every 10 seconds per bot. Going over answers 429: wait and try again.
  • A server can have up to 25 bots. Messages up to 2000 characters, 25 commands per bot.
  • Bots must follow the Zuno rules. Bots that spam, collect people's data or pretend to be Zuno get removed.

Full example (Node.js 18+)

const TOKEN = process.env.ZUNO_TOKEN;
const API = 'https://heyzuno.uk';
const headers = { Authorization: `Bot ${TOKEN}`, 'Content-Type': 'application/json' };
const api = (method, path, body) => fetch(API + path, { method, headers, body: body && JSON.stringify(body) }).then(r => r.json());

async function main() {
  await api('PUT', '/api/bots/@me/commands', { commands: [{ name: 'ping', description: 'Pong!' }] });
  let last = 0;
  for (;;) {
    try {
      const res = await fetch(`${API}/api/events${last ? `?last=${last}` : ''}`, { headers });
      const dec = new TextDecoder(); let buf = '';
      for await (const chunk of res.body) {
        buf += dec.decode(chunk, { stream: true });
        let i;
        while ((i = buf.indexOf('\n\n')) >= 0) {
          const block = buf.slice(0, i); buf = buf.slice(i + 2);
          last = Number(/^id: (\d+)$/m.exec(block)?.[1]) || last;
          const event = /^event: (.*)$/m.exec(block)?.[1];
          const data = JSON.parse(/^data: (.*)$/m.exec(block)?.[1] || 'null');
          if (event === 'command' && data.name === 'ping')
            await api('POST', `/api/channels/${data.channelId}/messages`, { content: 'Pong! 🏓', replyTo: data.messageId });
        }
      }
    } catch (e) { console.error('Disconnected, retrying…', e.message); }
    await new Promise(r => setTimeout(r, 2000));
  }
}
main();

Getting into the Bot Marketplace

Turning on Public bot lets anyone with your bot's add link put it in their server. To be listed in the Bot Marketplace, it gets a quick check by Zuno staff first:

  1. In Settings › Developer, open your bot and give it a clear name, a description and at least one command. Pick a category and tagline too.
  2. Press Submit for review (you can add a note for the reviewers, like which commands to try).
  3. Keep the bot running so staff can try it. You'll get a DM from Zuno when it's approved, or with what to change if it isn't.

Reviewers check that the bot works, does what its description says, and follows the rules.
